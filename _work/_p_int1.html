0先看结论：一句话回答「外面的世界怎么做的」

如果你只想记住一件事，就是这个。

结论：WorkBuddy 走的是「把文件扔进来 → 提示词 + 技能包 → 出文件」的外挂型路线，不碰企业系统； 而外面世界的 2025–2026 主流答案只有一条 —— 把企业系统用 MCP（Model Context Protocol，模型上下文协议）包成「工具」，让 Agent 直接调用。 这条路上已经有 ① 厂商官方（SAP / Salesforce / Dynamics 365 / Workday / ServiceNow / NetSuite / X）出原生 MCP Server； ② 连接器层（Composio / Zapier MCP / n8n / Workato / AnythingMCP）把成千上万个业务 API 变成工具； ③ 开源 ERP 自建（Odoo / ERPNext / 金蝶云星空 / ERP5）已能实测「17 秒查到库存、22 秒出财务表、直接审核单据」。 两者不是替代关系：外挂型解决「零改造、当天能用」，MCP 型解决「实时、可写、可审计」。真正的分水岭是你是否愿意动企业的系统。

反方观点也要听：2026-10-06，Ampersand 创始人 Lauren Long 在 X / LinkedIn 上公开写道「MCP is not an integration strategy（MCP 不是一套集成战略）」，并以 $15M A 轮（Bessemer 领投）为这一判断融资。她的核心论点：把 Agent 接到客户的 Salesforce MCP 上「是不够的」——真正的难点在客户的数据模型、权限、租户隔离与系统差异，那是集成问题，不是协议问题。 另有 WunderGraph《The Missing Layer in AI Agent Architecture》直接把 MCP 称作「企业级 AI Agent 架构的天花板」，以及 The New Stack《The MCP debate has a context problem》质疑上下文成本。

2四条技术路线：从「不改系统」到「住进系统里」

外面世界的做法不是一种，而是四层。越往下，能力越强、改造代价越大。

路线 A · 文件投喂（外挂型）

代表：WorkBuddy 693 方案 / ChatGPT 上传 / Claude Projects

  • 系统完全不动，人工导出 Excel/PDF/截图
  • 当天可用、零 IT 参与
  • 数据是「某一刻的快照」，读不到实时、写不回系统
  • 不可审计、不可追溯来源

路线 B · 只读查询（MCP / API）

代表：IQMS 只读 MCP / 厂商 Hosted MCP Server

  • 把系统按只读权限包成工具，Agent 直接查
  • 实时数据、可审计，风险最低
  • 需要开 API / 建 Server，但不必改业务逻辑
  • 多数企业落地从这一层开始

路线 C · 可写执行（带人类审批）

代表：金蝶 k3cloud MCP / ERP5 / CoolERP 记账

  • Agent 能建单、过账、审核、改状态
  • 必须叠加权限分级 + 审批兜底 + 审计留痕
  • 需要处理幂等、回滚、并发与人机边界
  • 风险与价值同时最高

路线 D · 嵌进系统 / 无 API 兜底

代表：钉钉悟空路线 C / RPA：UiPath、Skyvern、browser-use

  • 反向把 Agent 嵌进自家 CRM 页面里（用户无感）
  • 或用 RPA / 浏览器自动化操作没有 API 的老系统
  • 适合「改不动系统」又「必须动数据」的场景
  • 稳定性差、维护成本高，属兜底手段
