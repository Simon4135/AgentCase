## 四、怎么用

三个 HTML 页面（索引 / 分析 / 外部调研）左侧都带**常驻导航栏**：顶部是品牌与当前页信息；「本页导航」列出该页全部章节，点一下平滑跳到该节，滚动时自动高亮当前节；下方是「一键筛选」快捷按钮（索引页可按角色 / 行业 / 形态 / 技能包 / ROI 一键切换）与「相关页面」互链（三个 HTML + README + CSV 随时互跳）；页面底部计数会同步显示在侧栏底部。点侧栏标题右侧的 ⟪ 按钮或按键盘 [ 键即可**收起 / 展开**，收起后左上角出现 ☰ 按钮随时召回，选择会被记住。窗口宽度 ≤ 900px（平板 / 手机）时侧栏自动变成抽屉式：默认收起，点左上角 ☰ 滑出，点页面任意处或再次点 ☰ 关闭。

1. 看介绍 → 双击任意目录里的 场景引入.html，浏览器直接打开，无需联网。
2. 取提示词 → 打开该目录的 提示词与说明.md，四节结构：① 技能包安装命令 ② 推荐任务提示词（10 条）③ Live Demo 内提示词 ④ 场景引入正文。整段复制即可粘进 WorkBuddy。
3. 装技能包 → 技能包_XX.zip 是官方原件，可让 WorkBuddy 按 md 里的两条命令安装，或在 WorkBuddy 的「技能库」里上传这个 zip。
4. 全库检索 → 打开 索引.html：6 个筛选（行业 / 角色 / 形态 / 技能包 / 提示词 / ROI 量化）＋ 关键词搜索（标题·痛点·业务价值·技能名·角色·编号），点表头排序，点标题直接打开离线页面。
5. 看业务价值 → 索引.html 的「业务价值 / ROI 说明」列直接显示官方原文，点「展开价值详情 ▾」可看到该方案的最大差异点、价值说明、改造前后对照、会产出什么、量化表述、输入输出类型。
6. 看全局分布 → 打开 分析.html，分两部分：
   - **第一部分 · 业务维度**（9 节）：行业 / 角色 / 行业×角色矩阵 / 交互维度（输入→处理→产出）/ 形态 / ROI 量化 / 官方价值评分 / 最大差异点 / 价值主题词。
   - **第二部分 · 技术形态共性**（6 节）：一个解决方案的解剖（输入层→处理层→输出层）/ 你的 5 条技术判断逐条核实 / 与企业现有系统的真实关系（提及 ≠ 连接）/ 单点型 vs 端到端业务链 / 边界与局限 / **怎么选第一个**。
   - 任意条形、格子、词条、结论卡都可点开下钻到具体方案清单。
7. **挑第一个场景** → 分析.html 最后一节「怎么选第一个」给了 4 条优先信号、4 条要提前想清楚的信号，以及官方评分里「落地难度」的分布。
8. 表格处理 → 全量清单.csv 带 BOM，Excel / WPS 双击不乱码，含业务价值与 ROI 列。

## 五、业务价值与 ROI 的口径说明

本库的「业务价值 / ROI」全部**只取官方页面上写下的原文**，不做任何推断或拼凑。三个层次：

| 字段 | 来源（官方页面结构） | 覆盖 |
| --- | --- | --- |
| 最大差异点 | 「为什么这个场景值得做」卡片里以「最大差异点 ·」开头的那句 | 619 个方案 |
| 官方价值评分 | 同一张卡片里的公式：痛感 × AI 适配 ÷ 落地难度 = 分值 | 618 个方案 |
| 量化 ROI | 同一张对照卡内的「现在的做法 vs 交给 Agent 之后」，两侧都写出耗时才算 | 10 个方案 |

> 说明：官方页面的该卡片里还有两段与单个方案无关的方法论文字（评分公式的复述、「评分口径：…」的解释），已从价值字段中剔除，避免被误当作方案价值。
> 量化 ROI 之所以只有 10 条，是因为官方只在少数方案里把改造前后的耗时写在同一张对照卡上；跨段落配对数字会得到「1152 倍」这类不可核验的结论，故坚决不做。

## 六、技术形态共性（结论速览）

这一节是对 m01277 提出的 5 条技术判断做全语料核实后的结论，完整图文版见 `分析.html` 第二部分。核实范围：693 个方案的 HTML 正文 + 693 份 提示词与说明.md + 286 个技能包 zip（2153 个条目）。

| 判断 | 结论 | 支撑数字 |
| --- | --- | --- |
| 本质是「针对场景写提示词」，几乎没有代码型 workflow | **成立** | 286 个技能包含代码文件的 = **0 个**（只有 .md/.xlsx/.txt/.docx/.csv/.pdf）；每包必有 SKILL.md（286/286） |
| 几乎没有以 MCP 连接器接入的 | **成立** | 693 个方案里提到 MCP 的 = **2 个**（0.29%），且都写成「用户自行配置」的前提条件 |
| 是独立于企业系统的外挂型应用，不嵌入、不深度结合 | **成立** | 「嵌入现有系统 / 侧边栏 / 插件形式」= **0 个**；「用代码调接口」= **0 个**；「连数据库」= **1 个** |
| 输入是系统导出文件，输出也是独立文件 | **成立** | 技能包输入 1289 个文件中 .xlsx 占 1013；产出文件型 **693/693**，纯对话型 **0** |
| 几乎都是单点型场景，没有端到端业务链 | **成立但需补充** | 跨方案引用仅 **31 个**；「端到端」字面 39 个但多指方案自身完整；链条集中在 HR 域 |

另外发现三个未被提及、但同样显著的共性：

1. **全部 693 个页面都带免责声明**：「不宣称已接入客户生产系统，也不承诺任何效率提升百分比」（682 个逐字出现）。
2. **「人在环」是硬约束**：585 个方案明确要求人工审批 / 确认 / 复核 / 把关。
3. **官方主动降低了系统集成预期**：评分公式把「落地难度」当分母，需要先对接 POS / ERP 的场景分数会被压低；647 号方案原文即写「不能 —— Skill 不对接 POS / ERP 系统，经营数据需要手动提供」。
