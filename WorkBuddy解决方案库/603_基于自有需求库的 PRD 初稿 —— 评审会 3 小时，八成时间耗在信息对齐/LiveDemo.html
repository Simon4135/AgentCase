多币种转正进 v2.3 PRD · 上游三个场景的产出物就是原料

证据链来自 需求池多源收口与语义去重、竞品现状来自 竞品对比矩阵与讲标弹药、API 底账来自 API 文档与代码同步巡检

这份 PRD 现在还不能当排期基线：待决策 5 项需要评审会定夺、API 开放范围与弃用时间表与 发布说明与迁移指南起草 发版口径联动、定价议题商务未表态。

方案一：周三发预读摘要、周四评审会只过 5 个待决策项——多币种按 Q3 主线排，配置 3 项不等评审先行启动，内部零新增投入。

方案二：若跳过证据链直接拿通用模板 PRD 上会——评审会第一问「67 万哪来的」就答不上，第二问「竞品什么口径」又得回去查——一份没有出处的 PRD 在会上消耗的，是下次评审材料还有没有人认真看的信用。

追问现场可能被问到的

答不上来的问题，比答得漂亮的问题更能决定这场演示的结果

没有跑过 需求池多源收口与语义去重 的团队还能用这个场景吗？
能，但背景段退化为手工填写——证据链的厚度直接决定 PRD 的可信度；建议顺序是先跑 需求池多源收口与语义去重 攒一轮证据，再上 基于自有需求库的 PRD 初稿。
PRD 初稿会不会让评审会变成走过场？
恰恰相反：预读摘要把信息对齐挪到会前，会上的时间全部留给真正的分歧点——待决策清单就是为「有得吵」的议题准备的，工具不预设答案。
