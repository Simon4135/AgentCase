# PE 输入 研发新给了一版 P-IPC-01 的 BOM,放共享文件夹里了,Excel、PDF 和邮件都在。 帮我跟 ERP 导出的 v1.2 基线 对一下,差异列出来。 哪些地方你不确定的，也一并标出来，别替我拿主意。

Agent 接到后自己做的事

1

2

3

1

还没开始比对，先发现三份来源自己就对不上

这是最容易被跳过、也最要命的一步
料号字段Excel 里写的PDF 里写的Agent 的处理
M-FAN-002用量单位2 个2 套阻塞 一个风扇 vs 一套风扇组件，差价可能几倍
M-TERM-05用量1218阻塞 两份来源数量不一致，不能猜
这一步的看点 · 为什么这一步最值钱 如果直接拿 Excel 那份去比对，这两个问题永远不会被发现 —— 比对结果会显示得干干净净，然后带着错误一路走完审批、下采购单、发料。

单位那条尤其典型。行业里有过实打实的教训：一个零件单位把"个"写成"箱"，几十万物料闲置了半年。这类错误的特点是——它不会报错，它会安安静静地一路生效。

Agent 在这里没有自己挑一个"看起来更对"的值，而是直接把两处冲突标成阻塞项：研发自己发的两份文件都对不上，这个必须研发自己说清楚。

M-TERM-5		描述都是"接线端子 5.08mm 绿色"，编码差一个0，基线里两个都在用并成一个，废掉另一个

这一步的看点 · "一物多码"被抓住了 M-TERM-05 和 M-TERM-5是同一颗料，编码差一个零，基线里两个都在用—— 这就是行业里最普遍的那个病。它的后果很具体：两个编码两个库存账，系统显示这个没货就去紧急采购，回头盘点发现仓库里还堆着一批。

注意这一步对 AI 的准确率要求很低：它只需要把"描述很像但编码不同"的捞出来给人看，判不判得对无所谓 —— 人一眼就能确认。但只要命中一条，就省掉一次实实在在的损失。

这一步的看点 · 每条都写了"为什么这么判" 注意每张卡片上都有一行判断依据 —— 为什么判成新增（基线中查无此料号）、为什么敢判删除（新版没有且邮件里有交代）。

这一点看着不起眼，但制造业买的就是这个：能审。人可以推翻 AI 的任何一条判断，但推翻之前得看得见它凭什么这么说。一个不给理由的"已完成"，在这行没人敢签字。
4

Agent 把邮件正文和BOM 字段联起来了

这一条是老师傅才会注意到的
研发邮件正文里的一句话：
"主控板 M-PCB-001 现供货紧张，考虑到未来 6 个月产能，请PE 评估。"
Agent 的推理 单看BOM，M-PCB-001 的替代料字段从"有 M-PCB-002"变成了空 —— 这最像是研发导出时漏填了。
单看邮件，"供货紧张，请 PE 评估"是一句很容易被当成客套话滑过去的提醒。

但这两件事放在一起，意思就完全反了：替代料不是漏填，是研发故意留空，在等 PE 接话 —— 他想说的是"原来那颗替代料现在也不保险了，你重新定一个"。

如果按"漏填"处理，PE 会顺手把M-PCB-002 填回去，然后带着这个已经不成立的替代关系走完审批。等采购按它下单，才发现这条路早就堵了。

所以 Agent 的建议不是"补填替代料"，而是：这颗料的替代关系必须在审批之前重新定义，先找研发确认，别让它带着模糊状态往下走。

5

每条改动牵动多少钱 · 这一层是给老板看的

把技术动作翻译成金额和风险
变更项牵动的未完工工单已下采购 / 在途旧料库存金额要做的事
M-USBB-01删除2 张· 共 60 台在途 200 个¥4,800联系供应商能否退/ 改用在其他机型

M-USBC-01新增—未下单—新料要先建档、询价、定供应商
这一步的看点 · 为什么这一层最能打动决策者 前面几步的产出，工程师看得懂、也知道有用。但这一张表是给老板和主管看的 —— 它把"机柜箱体版本从 v2 改到 v3"这句技术描述，翻译成了"仓库里还压着 6.24 万的 v2 箱体，你打算怎么办"。

这也是变更评审真正要拍的板：不是同不同意改，而是旧料怎么处理、在途怎么办、什么时候切版本。没有这张表，评审会就是各部门凭印象争。
⚠ Agent 的结论：这份变更现在还不能进ERP
有2 处来源冲突（单位"个/套"、用量 12/18）和 1 项替代关系未定，这三项都必须研发先说清楚。

但不影响先动起来 —— Agent 把能推进的和卡住的分开了：
• 可以先走的：Type-C 新增、USB-B 删除、箱体版本修订这 3 项，依据清楚，可以直接写进变更单送审
• 必须先澄清的：单位冲突、用量冲突、替代关系 —— 已自动生成一份问题清单，3 个问题一次问完，不用来回三趟
• 顺手要处理的：M-TERM-05 / M-TERM-5 这对重复料，跟本次变更无关，但既然发现了就一并清掉
之后

这一次核对完，公司多了什么

不是省了几十分钟，是少了几个隐患
✓
两个本来会溜过去的错误被拦下了 —— 单位"个/套"和用量 12/18。这类错误不会报错，只会安静地一路生效到停线或退货。
✓
一对重复料被清掉了 —— M-TERM-05 / M-TERM-5。跟这次变更无关，但少一个重复码，就少一份将来对不上账的可能。
✓
一次把问题问全了 —— 3 个待澄清项一张清单发给研发，不是发现一个问一次、来回三趟。
✓
留下了可追溯的依据 —— 每条判断为什么这么判都写着。将来复盘"这个改动当初谁批的、凭什么批"，有据可查。
✓
PE 的角色变了 —— 从"逐行核对 + 手工敲格式"，变成"看Agent 标出来的可疑项，做判断"。省下的时间花在了判断上，不是眼力活上。
