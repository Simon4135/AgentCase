### 一、这件事现在是什么样

*门店店长 / 品牌研发 · 上新满两周的那次复盘*

某中式快餐品牌「御膳坊」，2026 夏季上新满两周。3 道新菜上了菜单，店长被区域经理问「新菜卖得怎么样」，只能翻出 POS 说「藤椒鸡腿饭卖得不错」—— 不错是多少、毛利贡献多少、有没有抢老菜的生意，没人算过。招牌牛肉面这两周销量掉了不少，是天热还是新菜抢的，说不清。上周区域会上另一家店下架了一道新菜，全凭店长感觉，下架后才发现那道菜带走了一批固定客。研发问「哪道该留、哪道该调、哪道该下」，没有量化依据，讨论变成各说各话 —— 一份评估报告手工做要 3 天，结论出来时上新窗口已经过了。

### 二、痛点 · 每条都发生在昨天

*不是流程描述，是门店与研发每次上新真实经历的消耗 —— 以下内容取自场景调研*

1新菜效果缺乏量化评估：销量、毛利、菜单占比三个维度没人算，「卖得不错」四个字应付所有追问

2蚕食老菜不自知：新菜销量里有多少是从老菜抢来的，招牌面掉了近两成销量才发现

3下架决策靠拍脑袋：留、调、下架没有统一标尺，下架错了带走一批固定客

4评估耗时、决策滞后：一份评估报告手工做 3 天，结论出来时上新窗口已过

### 三、换个做法之后

*变化不在「快」，在「有标尺」和「敢决策」*

✕ 现在的做法
效果评估凭感觉，「卖得不错」应付所有追问
蚕食效应没人算，老菜掉了销量找不到原因
留/调/下架拍脑袋，下架错了才知道
报告手工做 3 天，决策错过上新窗口

    ✓ 交给 Agent 之后
三维评分：销量贡献/毛利贡献/菜单占比，每维 0-100 分含达标线
蚕食识别：上新前后逐菜对比，下降 >15% 标出 + 净增量算总账
生命周期判定：导入/成长/成熟/衰退四阶段，留/调/下架有统一标尺
1 份评估报告从 3 天压至 20 分钟，每条建议溯源到具体数据点

### 四、场景闭环

*5 步 · 每一步的产出都是下一步的输入*

第 1 步
数据接入 · 字段归一化解析 CSV / Markdown / Excel，归一化日期/菜品名称/是否新菜/销量/单价/成本，标注上新前后两阶段
第 2 步
三维评分 · 含达标线销量贡献 / 毛利贡献 / 菜单占比，每维 0-100 分
第 3 步
蚕食效应 · 下降>15% 识别对比上新前后各菜品销量变化，识别被蚕食菜品 + 净增量计算
第 4 步
生命周期判定 · 四阶段基于销量趋势判定导入/成长/成熟/衰退，输出趋势预警
第 5 步
决策建议 · 留/调/下架三维达标+净增量为正→留菜；部分未达标→调菜；未达标+衰退→下架；Markdown 必备 + HTML/Word/PPT 同步产出

    要准备什么
菜品销售数据文件
CSV / Markdown 表格 / Excel 任意一种，含上新前 7-14 天 + 上新后 7-14 天的菜品级记录（日期/菜品名称/是否新菜/销量/单价/食材成本/分类）

上新日期 + 新菜清单
按上新日期自动标注前后阶段；无「是否新菜」字段时自动判定

品牌名 + 上新批次
报告抬头必填，如「御膳坊 2026夏季上新效果评估」

    为什么这个场景值得做

      痛感 4 × AI 适配 5 ÷ 落地难度 2 = 10.0

      最大差异点 · 决策有标尺：三维评分含达标线、蚕食识别有 15% 阈值、净增量算总账 —— 留/调/下架每条建议可溯源到具体数据点，不靠拍脑袋。

      评分口径：痛感看「这事没做好谁会生气、生气到什么程度」；
      AI 适配看「输入是否非结构化、是否要跨渠道取数、错了能不能当场看出来」；
      落地难度是分母 —— 需要先对接 POS/ERP 才能用的场景，分数会被压得很低。
