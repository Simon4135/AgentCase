触发

批包装结束，物料平衡算完是 100.00%

按现有规程，这一栏已经过了 —— 而它核的是数量，不是码值

邹立辉刚把 KT26-0815 的印刷包材物料平衡算完，四种包材全部 100.00% 闭合。班长蒋敏已经复核签字。按规程，批记录现在可以移交现场 QA 审核。

问题在于：这张表从上到下没有一栏记录码值。而追溯码的问题恰好出在码值上。

物料名称领用数使用+未用+残损+退库+销毁平衡率记的是什么
小盒1200011742 + 0 + 168 + 78 + 12 = 12000100.00%数量
说明书1200011742 + 0 + 156 + 90 + 12 = 12000100.00%数量
中盒600587 + 0 + 8 + 5 + 0 = 600100.00%数量
大箱6258 + 0 + 2 + 2 + 0 = 62100.00%数量

四种包材全部闭合。这一步不是要推翻它 —— 数量层面它是对的。要说清的是它管不到的那一层。

这一栏为什么发现不了码值问题物料平衡的算式是加减法：使用 + 未用 + 残损 + 退库 + 销毁 = 领用。只要每一类的个数没记错，平衡率就是 100%。

而「哪 168 个」是集合问题，不是加减法能表达的。如果有 3 个码被错分到了「残损」而实际仍在线、同时另有 3 个码在线却被记成残损，两边各差 3 个、净差 0 个，平衡率依然是 100.00%。

这不是填表的人不认真，是这张表的设计管不到这一层。
1

要素校验 · 先确认这两份材料能不能对账

口径不一致就先归一，否则比出来的差异是假的

对账前必须先确认两件事：作废码清单是否覆盖了本批的全部作废动作，以及物料平衡的「残损数」口径是否与之对应。

核对项批记录侧赋码系统侧口径是否一致处理
作废动作类型只有「残损数」一栏剔除 / 替换 / 解除 三类需归一三类合并计入「残损」后再比
是否含已打批号未用本企业 SOP 要求计入实际值不涉及一致本批该栏为 0，不影响
层级范围小盒/说明书/中盒/大箱本次导出仅小盒层需缩范围本次只对账小盒层，其余层单独排期
时间范围本批包装期间按批次号导出一致无需处理
合计 4 项——2 项需归一归一后可对账

归一之后，本次对账范围明确为：小盒层、本批、三类作废动作合并。中盒与大箱层的作废码需要另外导出，本次不纳入结论。

为什么先做这一步如果不先归一就直接比，会得出一个假差异：赋码系统的「替换」类在批记录里可能被记成退库而不是残损，比出来的差额是口径造成的，不是真问题。

这一步的产出是「本次结论的适用范围」 —— 中盒与大箱层没有导出作废码，所以这两层本次说不了话。报告里必须写清这一点，而不是让人误以为全批都核过了。

到这里为止，一切正常这一步的价值是把「看起来没问题」这件事讲清楚。

现场演示时这一步要停一下，问客户一句：「到这里你们会继续往下查吗？」

答案通常是不会 —— 因为数量对上了，而且没有任何规程要求继续查。下一步要做的事，在企业现有流程里没有对应动作。
3

码值层比对 · 逐条查这 168 个码现在是什么状态

这一步是全场景的核心：从「几个」变成「哪几个」

把作废码清单里的 168 个码逐个拿去查当前关联状态。按定义，被作废的码应当处于「已解除」状态。

作废类型条数状态应为实际「已解除」实际「已关联」异常
剔除（喷码不清）162已解除1620无
替换（原码作废）3已解除033 条应作废却仍在线
剔除（设备误判）3已解除30无
合计168—16533 条异常

另一个方向也要查：有没有码实际在线、却被记进了残损。拿采集日志的关联成功清单与物料平衡的「使用数」比对，发现 3 个码在采集侧关联成功、但被计入了残损 168 之中。

两个方向各 3 条，净差 0 —— 所以物料平衡永远是 100.00%。

从历史里想起了公司踩过的坑2026 年 3 月有一批出现过药店反馈「扫码显示未激活」，当时的处理是「重新上传了一次」，问题消失，记录停在这里没有做原因分析。

把那一批的作废码清单也导出来比了一遍，发现同样存在「应在线却被误作废」的码 —— 当时不是上传失败，是码被误作废了，重新上传只是覆盖掉了错误状态。也就是说同一个机制已经发生过一次，只是没人认出来。

这条不靠当年经手的人还在不在职 —— 它是从两份系统导出文件里比出来的，不依赖任何人的记忆。

影响定位 · 说清这 6 条各自意味着什么

两个方向的后果完全不同，处置方式也不同
异常类型条数码值后8位现实后果处置方向
应作废却仍「已关联」3…40273915 / …40273916 / …40273917对应小盒可能已随货流出。企业认为它已作废，而药店扫码可查先在平台侧确认是否已被扫码销售
应在线却被误作废3…40268442 / …40268443 / …40268501对应小盒在货架上，药店扫码会显示未激活或状态异常核实后按平台功能恢复或重新关联
合计6——两类分开处置

这两类不能合并成「6 条异常」一句话报上去。第一类涉及可能已流入市场的产品，第二类是在库产品的状态错误 —— 前者要报质量部，后者赋码岗自己能处理。

把技术动作翻译成钱3 条「应作废却仍已关联」的码，如果对应小盒已流入市场并被扫码，会形成重复码记录。

医保规则说得很直接：一盒药品的追溯码只应有一次被扫码销售的记录，若重复出现多次，可能存在假药、回流药或药品被串换销售等情况；而 2025 年 7 月 1 日起，定点医药机构销售环节按要求扫码后方可进行医保基金结算，截至 2025 年 6 月已累计归集追溯码 398.85 亿条。

违规的后果是解除医保协议并处 2 倍罚款。所以这一栏要算的不是这 3 盒的货值，是这个品种在医保渠道的销售资格 —— 这 3 条不是 3 个码的事。

② 替换动作后必须当场复核原码状态 —— 由班长蒋敏在复核签字时增加这一项，本周内更新岗位 SOP，验收标准是抽查三批的替换类码状态全部为「已解除」。

该拦的地方拦住了结论是这批的批包装记录现在还不能移交 QA 审核。

依据是 GMP 第二百一十五条：「在物料平衡检查中，发现待包装产品、印刷包装材料以及成品数量有显著差异时，应当进行调查，未得出结论前，成品不得放行」 —— 码值差异最终会体现为数量差异，属于应当调查的情形。

方案一：赋码岗自己查 08-18 那天的系统操作日志，确认这 6 条的操作过程，约半天。若属操作失误则按偏差流程走，不影响其余 11736 个码的放行准备 —— 也就是说这批货不必整批等着。
方案二：对 3 条「应作废却已关联」的码，先在平台侧确认是否已被扫码销售。若未被扫码，可通过平台的注销功能处理；若已被扫码，必须立即报质量部 —— 这已不是记录问题。
这批的批包装记录现在还不能移交审核 —— 码值层有 6 条差异未查清
数量层是干净的：四种包材全部 100.00% 闭合，168 == 168。但码值层有 6 条差异：3 条应作废却仍「已关联」、3 条应在线却被误作废。两个方向各 3 条、净差 0，所以物料平衡这一栏永远发现不了。

按 GMP 第二百一十五条，数量有显著差异时未得出结论前成品不得放行，而码值差异最终会体现为数量差异 —— 属于应当调查的情形。

不用整批干等的两个方案：
方案一 · 查系统日志（约半天，赋码岗自己能做）：调 08-18 当天替换与残损归类两个动作的操作日志，确认这 6 条的操作过程。若属操作失误按偏差流程走，其余 11736 个码的放行准备照常进行 —— 这批货不必整批停。
方案二 · 平台侧优先确认那 3 条（约 1 小时，但必须先做）：确认 3 条「应作废却已关联」的码是否已被扫码销售。未被扫码则通过平台注销功能处理；已被扫码则立即报质量部 —— 因为这时涉及的是可能已流入市场的产品，且重复码会触碰医保结算规则（重复结算可致解除协议并处 2 倍罚款）。

放行结论与责任认定两栏留空 —— 这两栏归质量部与质量受权人。

追问现场可能被问到的

答不上来的问题，比答得漂亮的问题更能决定这场演示的结果

法规都没要求记作废码，为什么要做这件事？
正因为法规没要求，所以没人做 —— 这是制度空缺不是违规。但两件事绕不过去：一是 GMP 第二百一十五条要求数量有显著差异时未得出结论不得放行，码值差异最终会体现成数量差异；二是医保扫码结算已经把它变成了现金流问题。顺便说，同一套 GMP 体系的兽药版 2020 年已经补上了这一栏。
能不能直接把那 3 个码在系统里作废掉？
不能。码的作废、解除、替换、平台注销都是系统内的受控操作，而且已上传的必须走平台的注销功能。我们只出差异清单和建议核实动作，操作由赋码岗本人执行 —— 这一条不是保守，是因为这些操作本身要留审计追踪。
我们的作废码导不出来怎么办？
先问一句是导不出来还是没导过。厂商的功能清单里这一项是标配，现实中绝大多数情况是从来没人导过，因为没有任何要签字的文件需要它。如果确实导不出来，这个场景就先不做 —— 这份清单是它唯一不可替代的输入。
