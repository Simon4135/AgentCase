代码包可以演示，但两类复核必须在发布前完成
Skill 的铁律写得很清楚：支付模块/用户授权/隐私协议标注「建议人工复核确认」。两处尤其不能省：

复核点 1 · 代码安全性与测试覆盖：AI 生成代码可能存在安全漏洞或不符合最新小程序规范，自动测试以核心交互为主 —— 开发主管须复核代码安全性与 API 兼容性，开发人员须补充边界用例与异常测试。
复核点 2 · 发布合规：隐私协议与用户协议为模板，不同小程序类目审核要求不同 —— 发布前须由法务复核协议内容并适配类目要求；代码须适配 AppID/域名/业务资质后方可提交。

给出的不是「改完再生成一遍」，而是：项目结构、页面代码、测试报告直接用，安全性与合规两处处方级把关 —— 复核一天，比三周从零开发仍快一个量级，且检查项一项不漏。

追问现场可能被问到的

答不上来的问题，比答得漂亮的问题更能决定这场演示的结果

生成的代码能直接上线吗？
不能零修改直接上线 —— 代码须适配 AppID/域名/业务资质，开发主管复核安全性与 API 兼容性，法务复核协议后，才能提交微信官方审核。
能接真实支付吗？
不处理 —— Skill 的边界明确不含真实支付对接，下单走 Mock。资金环节须由持牌支付通道与人工接入完成。
91.3% 的测试覆盖率够吗？
那是用例通过率，不是覆盖率 —— 自动测试以核心交互为主，边界条件与异常场景可能遗漏，开发人员须补充边界用例后再谈「够」。
